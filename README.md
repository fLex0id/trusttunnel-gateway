# TrustTunnel: сервер и шлюз

Свой VPN из двух серверов на базе [TrustTunnel](https://github.com/TrustTunnel/TrustTunnel) (AdGuard).
Устройства подключаются обычным WireGuard к шлюзу в России. Российские сайты шлюз открывает сам,
остальное отправляет через TrustTunnel на сервер за рубежом. Посторонний, открывший сервер
в браузере, видит обычный сайт.

```
телефон, ноутбук ──WireGuard──▶ шлюз (РФ) ──┬── российские сайты: напрямую
                                             └── всё остальное: TrustTunnel ──▶ сервер (за рубежом) ──▶ интернет
```

## Установка

На каждом VPS под root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/fLex0id/trusttunnel-gateway/main/install.sh)
```

Скрипт покажет экран приветствия и спросит, что ставить на этот VPS.

1. **Сервер за рубежом** — ставится первым. Нужен домен с A-записью на IP сервера и свободные порты 80 и 443.
   В конце установки сервер покажет ссылки `tt://` для приложений TrustTunnel и **ключ подключения шлюза** — строку `ttgw:…`.
2. **Шлюз в России** — ставится вторым. Вставьте ключ подключения, когда установщик его спросит.
   В конце шлюз покажет QR-коды для приложения WireGuard.

Сервер работает и сам по себе: телефоны можно подключать к нему напрямую приложением TrustTunnel или AdGuard VPN.

**Требования:** Rocky Linux 9/10 или Debian 12/13 (Alma, RHEL, Ubuntu должны работать, но не проверялись),
systemd, x86_64 или aarch64, от 512 МБ RAM — при нехватке памяти скрипт сам добавит swap.

## Управление

После установки всё делается командой `tt`: без параметров открывается меню, `tt help` — список команд.

| Сервер | Шлюз |
| --- | --- |
| `tt users` — пользователи и кто подключён | `tt list` — клиенты и кто на связи |
| `tt add ИМЯ` / `tt del ИМЯ` | `tt add ИМЯ` / `tt remove ИМЯ` / `tt show ИМЯ` |
| `tt link ИМЯ` — ссылка `tt://` и QR-код | `tt endpoint КЛЮЧ` — сменить сервер |
| `tt key ИМЯ` — ключ подключения шлюза | `tt ru …` — российские сайты напрямую |
| `tt dns` — DNS для приложений | `tt udp auto` — проверить UDP через туннель |

Общие: `tt status`, `tt update`, `tt speedtest`, `tt doctor`, `tt uninstall`.

## Что внутри

**Сервер.** TrustTunnel на 443 (HTTP/2 по TCP и HTTP/3 по QUIC), сертификат Let's Encrypt (acme.sh или certbot)
с автопродлением без разрыва подключений. Сайт-заглушка: всем, кто зашёл без пароля, TrustTunnel показывает
обычный сайт; на попытку подключиться с неверным паролем отвечает 404, как обычный сайт, а не 407, как прокси.

**Шлюз.** WireGuard → перехват nftables (TPROXY) → sing-box → клиент TrustTunnel.
- Российские сайты (банки, Госуслуги, маркетплейсы, операторы связи, Яндекс, VK; списки v2fly `category-ru` и др.,
  IP-адреса РФ) идут напрямую, заблокированные в РФ (список itdoginfo) — всегда через туннель.
  Всё, что не попало в списки, — через туннель.
- Два DNS: для зарубежных сайтов — шифрованный, через туннель (Cloudflare, Quad9, Google, OpenDNS, NextDNS);
  для российских — напрямую (Яндекс и другие). DNS устройств перехватывается.
- Если туннель упал, интернет у устройств пропадает, а не идёт напрямую. IPv6 через шлюз не пропускается.
- Сторож раз в минуту проверяет туннель и перезапускает клиент; по желанию пишет в Telegram.

## Как устроено

- Все настройки — в `/etc/tt/tt.conf`. Меню меняет только его, затем одна операция «применить»:
  собрать конфиги, проверить, атомарно подменить, перезапустить, убедиться, что работает, иначе откатить.
- Бинарники TrustTunnel берутся из официальных релизов и проверяются по подписи GPG (ключ AdGuard встроен).
- Обновления только вручную (`tt update`), с копией и откатом.
- Списки РФ обновляются раз в неделю через туннель. Новый список заметно меньше прежнего не принимается.
- Исходники — в `src/`; `python3 build.py` собирает один файл `dist/tt.sh`. Проверки (ShellCheck, тесты
  генераторов на Python 3.9+) запускаются в GitHub Actions; релиз собирается из тега.

## Честно о маскировке

Сервер выглядит как обычный сайт и не отвечает как прокси. Но при пристальном анализе — объём и время трафика,
отпечаток TLS — VPN можно распознать. Это свойство любого VPN, а не этих настроек.
